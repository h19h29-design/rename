## 사용 순서

1. **파일 추가**: 여러 문서를 한 번에 선택할 수 있습니다.
2. **항목 설정**: 이름·주민등록번호·생년월일이 기본 선택입니다. 필요할 때 금액·일반 날짜를 켭니다.
3. **변환 방식**: 구분 가능한 대체값 / 전체 마스킹 / 완전 삭제를 선택합니다. 자동으로 놓칠 수 있는 이름은 직접 입력합니다.
4. **개인정보 탐지**: 원본·대체값·횟수·발견 위치를 확인합니다. 같은 이름은 여러 문서에서도 같은 대체값으로 바뀝니다.
5. **검토**: 체크를 해제한 후보는 그대로 남깁니다. 대체값 칸을 두 번 눌러 수정합니다. 유형을 필터링한 뒤 **보이는 항목 일괄 대체**를 누르면 금액 `0`, 날짜 `2000-01-01`처럼 지정할 수 있습니다.
6. **새 파일 저장**: 검토 확인란을 선택하면 저장할 수 있습니다. 이미지가 있으면 별도의 직접 확인도 필요합니다.

| 항목 | 기본 대체 예시 | 다른 방식 |
|---|---|---|
| 이름 | 홍길동 → 대상자001 | `***`, 빈칸, 직접 지정한 가명 |
| 주민등록번호 | 주민등록번호 형태 → `[주민등록번호001]` | `******-*******`, 빈칸 |
| 생년월일 | 1990-01-01 → `[생년월일001]` | `****-**-**`, 빈칸, 직접 지정 |
| 금액 — 선택 | 1,234,500원 → `[금액001]` | `0` 등 직접 지정 |
| 일반 날짜 — 선택 | 2026-09-13 → `[날짜001]` | 고정 날짜 등 직접 지정 |

대응표는 디스크에 저장하지 않습니다. 처리결과 JSON에는 개수·경고만 기록하며 원문·원본 파일명·원본 경로는 기록하지 않습니다. 결과 파일 이름도 `익명화_001.xlsx`처럼 새 이름을 사용합니다.

## 지원 형식

| 입력 | 결과 | 추가 프로그램 |
|---|---|---|
| `.xlsx` | `.xlsx` | 필요 없음 |
| `.hwpx` | `.hwpx` | 필요 없음 |
| `.xls` | `.xlsx` | Windows에 설치된 Microsoft Excel |
| `.hwp` | `.hwpx` | Windows에 설치된 HWPX 저장 지원 한글 |

HWP는 한글 COM으로 HWPX로 변환한 후 처리합니다. 한글의 파일 접근 승인 창이 표시될 수 있습니다. 보안 우회 DLL 설치나 레지스트리 변경은 하지 않습니다. **한글/Excel이 없는 PC에서는 먼저 다른 PC에서 XLSX/HWPX로 저장해 주세요.**

### 엑셀 결과는 공유용 정적 복사본

셀 서식·병합·기본 시트 구조를 최대한 유지하며 숨김 시트·행·열도 처리합니다. 다만 개인정보가 수식·캐시에 남는 것을 줄이기 위해 **수식은 파일에 저장된 결과값으로 고정**합니다. 저장된 결과값이 없는 수식은 빈칸이 됩니다. 원본을 Excel에서 계산·저장한 뒤 처리하는 편이 좋습니다.

공유 문자열을 실제 셀 문자열로 바꾼 뒤 기존 공유 문자열 저장소를 없애 미사용 원문이 남는 것을 방지합니다. 메모·작성자 속성·하이퍼링크·이름 정의·조건부 서식·데이터 유효성 규칙은 제거합니다. 차트·피벗·매크로·첨부 개체·변경 이력과 외부 연결·쿼리·DDE·컨트롤 속성·대화상자 시트 XLSX 파트는 지원하지 않고 차단합니다.

### 한글 결과의 레이아웃

본문과 표 등 텍스트를 처리하고, 여러 글자 서식으로 나뉜 문자열도 치환합니다. 텍스트 미리보기를 다시 만들고 이미지 미리보기를 비우며, 작성자 속성과 문서 스크립트도 정리합니다. 치환 문자열 길이에 따라 줄바꿈·쪽 배치가 달라질 수 있으므로 실제 한글에서 결과를 확인해야 합니다.

## 탐지 범위와 한계

이름은 성명/이름 등의 제목·표 열과 직접 입력한 문자열을 사용합니다. **문맥만으로 모든 사람 이름을 찾아내는 AI는 아닙니다.** 띄어 쓴 한글 이름도 대상으로 하지만, 일반 단어와 같은 이름은 오탐할 수 있습니다. 생년월일은 제목/열 문맥이 없으면 일반 날짜와 구분하지 못할 수 있습니다.

이미지·스캔본·서명·도장 속 글자는 인식/삭제하지 않습니다. 주소·전화번호·계좌번호·이메일·직위 등도 기본 자동 탐지 대상이 아닙니다. 이미지가 남은 결과는 추가 개인정보를 포함할 수 있습니다. 선택을 해제한 원문도 그대로 남습니다.

암호 문서는 지원하지 않습니다. 파일당 64 MB, 한 번에 최대 50개, 전체 압축 파일과 전체 압축 해제 크기 각각 256 MB로 제한합니다. 위험한 ZIP 경로·DTD/XML 엔터티·불투명한 첨부 데이터는 차단합니다. 처리 전후 원본 해시를 확인하며, 미리보기 후 재검사는 최대 파일 크기만큼만 다시 읽는 상한 제한 방식입니다. 모든 결과의 변환·재검사를 마친 뒤 새 결과 폴더를 공개합니다.

구형 파일 변환에는 Windows 사용자 임시 폴더가 필요하며 정상 종료 시 삭제합니다. 강제 종료 시 파일이 남을 수 있고 보안 삭제를 보장하지 않습니다. 설치된 Office의 추가 기능·보안 설정, 사용자가 선택한 동기화/공유 폴더 동작은 별도이므로 기관 정책을 따르세요.

## 개발 / 빌드

Python 3.11 이상, 권장 3.12 64비트. UI는 기본 Tkinter, XML 처리는 lxml, 구형 파일 연동은 pywin32를 사용합니다. 외부 AI API나 서버가 없습니다.

```powershell
.venv\Scripts\python -m pip install -r requirements-dev.txt
.venv\Scripts\python -m pytest -q
.venv\Scripts\python build_windows.py
```

또는 `BUILD_WINDOWS.cmd`를 실행합니다. Windows에서 테스트 → PyInstaller 패키징 → 패키징된 실행 파일 UI 스모크 테스트 → ZIP/SHA256 생성 순서로 실행됩니다. Linux 테스트는 `xvfb-run -a python -m pytest -q`로 실행합니다.

`docs/VALIDATION.md`에 검증 범위와 실제 Windows/Hancom 수동 확인 항목을 구분해 기록합니다. 합성 문서 테스트 통과를 실제 한글에서의 문서 열림·완전한 개인정보 제거 보장으로 해석하면 안 됩니다.
